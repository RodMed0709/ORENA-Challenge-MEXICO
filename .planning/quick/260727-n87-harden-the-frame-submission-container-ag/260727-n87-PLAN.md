# Quick task 260727-n87 — harden the submission, then actually run it

## Why

Submission 01 scored 0.4710 and the adversarial audit established it was **not broken** — frames
arrived, the prompt was byte-identical, generation matched, offline held, the Dockerfile is
byte-identical to the template's. But it shipped with defects that did not fire this time and
would each cost a whole submission slot silently:

- We never read **`/input/batch.json`**, which the organizers' own fixture uses to *declare* the
  frame layout: `{"qIDs": [...], "batch_size": 3, "layout": {"frames": "frames/<qID>.png"}}`.
  Verified against the live template. The ZIP-vs-directory ambiguity that nearly sank submission 01
  was answered by the platform, machine-readably, and we guessed instead.
- `rglob("*.png")` is case-sensitive on Linux. `.PNG`/`.jpg` → empty index → **score exactly 0**.
- `inference.py` detects "N of M qIDs have no frame" and only **logs** it. Exit 0, valid
  `answer.json`, `no_response: 0`, score 0, no diagnosis.
- `device_map = "cuda" if torch.cuda.is_available() else "cpu"` degrades silently. Measured: bf16
  on CPU did not finish **one question in 35 minutes**.
- The ZIP extraction is unguarded — a bad archive produces **no** `answer.json` at all.
- Deps are floors, not pins, against the `CLAUDE.md` requirement.

And the template prescribes `do_test_run.sh`, which we never ran: **this container has never
emitted an `answer.json`**. The only pre-submission test was a CPU smoke of startup and model load.

## Tasks

### Task 1 — harden `inference.py`

**files:** `experiments/06-vit-lora/_tools/submission/inference.py`

**action:**
1. New `read_batch_manifest()` → parse `/input/batch.json` if present; return `qIDs`, `batch_size`,
   `layout`. Never fatal — a missing/!malformed manifest falls back to today's behaviour.
2. `build_frame_index(layout)` — when `layout["frames"]` is given (e.g. `"frames/<qID>.png"`),
   resolve the directory and suffix from the pattern and index by that. Otherwise keep the existing
   directory-then-ZIP preference. In every path, match **case-insensitively** across
   `{png,jpg,jpeg,bmp,webp}` and add a last-resort sweep for image files anywhere under `/input`.
3. Wrap the ZIP open/extract in `try/except` — log and continue to the fallback rather than
   propagating out of `run()`.
4. `require_cuda()` — raise unless `torch.cuda.is_available()` or `ALLOW_CPU=1`.
5. Circuit breaker: after the loop, `return 1` when `n_failed > len(requests) // 2`. **Write
   `answer.json` first** — a partial answer file is strictly better than none, and the non-zero
   exit is what makes the failure loud.
6. Cross-check `batch_size` against `len(requests)`; warn on mismatch.
7. Update the module docstring: drop the now-settled ZIP-vs-directory prose, state that the layout
   is read from `batch.json`.

**verify:** `python -m py_compile`; a local dry run against a hand-built fixture with mixed-case
and mixed-extension frame names indexes all of them.

**done:** committed.

### Task 2 — pin the dependencies

### Task 3 — run it end-to-end on the organizers' fixture

**files:** none in-repo (produces evidence)

**action:** On a RunPod GPU pod attached to volume `gf78k60nlt`:
1. Fetch `frame-algorithm/test/input/interface_1/` from the official template (request.json,
   batch.json, FO_definitions.json, frames/q00{1,2,3}.png).
2. Point `INPUT_PATH`/`OUTPUT_PATH` at it and run the hardened `inference.py` with
   `MODEL_PATH` = the merged rung-06 `checkpoint-1720` already on the volume.
3. Verify `answer.json`: exactly one response per qID in `request.json`, qIDs matching, `content`
   non-empty, schema `{qID, content, latency}`.
4. Adversarial variants on the same fixture, all cheap: uppercase `.PNG`, a `batch-frames.zip`
   instead of `frames/`, and an empty frame dir (must now exit non-zero).
5. Stop the pod.

⚠️ **Docker is not exercised.** RunPod pods have no Docker daemon, so this runs the container's
*logic*, not its image. That is the right trade: the `Dockerfile` is already verified
byte-identical to the template's, so the residual risk lives in `inference.py`, which this covers.
State this limitation in the summary rather than implying a full container test.

**verify:** `answer.json` exists with 3 non-empty answers; the empty-dir variant exits non-zero.

**done:** evidence in the summary, pod stopped.

## Out of scope (stated)

- **The judge mismatch.** The SDK default `Qwen/Qwen3.5-4B` does not exist on HF; we use
  `Qwen3-4B`; the platform uses something undocumented. 29% of the `object_recognition` ID bucket
  is judge-scored. Real, acknowledged by the user as a limitation, not fixed here.
- **Versioning `do_build.sh` / `do_test_run.sh` / `do_save.sh`.** The template ships them and ours
  are not in git, which is exactly why the validating step was skipped. But `CLAUDE.md` forbids
  `.sh` launchers outright. Flagged for the user to rule on; not decided unilaterally.
- **The model itself.** A 4B beats us by 4.5 points on the same 2000 questions. Nothing here
  touches that.
