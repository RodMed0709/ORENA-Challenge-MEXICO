<objective>
Write the ONE new class the challenge platform ever calls: `QwenInferenceEngine` with the SDK's frozen `load()` + `predict(sample) -> str` contract (MODEL-01), plus the temp-clip frame sampling + unlink (MODEL-02) and the Phase-2 output floor guard. This is where the three bugs in `examples/inference.py` get fixed: (1) the `device_map` branch that never fires for `"cuda:0"`, (2) feeding the whole clip as a `"video"` (visual-token blowup → >5s timeout), and (3) unbounded `max_new_tokens=128` with no greedy flag. The real-model load is GPU-marked (authored here, run on RunPod); everything else is CPU-tested with mocked model/processor + the StubEngine scaffold from 02-01.

Purpose: `predict()` is the only surface the platform invokes, so its interface is frozen by the SDK — no base class, no signature change (CONSTITUTION §I.2). For the zero-shot number to be an ALWAYS-VALID floor even at zero-shot, `predict()` must already survive the silent gates: greedy + low `max_new_tokens` + a hard <=300-char truncation (the OpenEnded/Matching parse gate raises `ValueError` >300 chars → auto-incorrect) and an AdversarialDetector self-scan (a flagged phrase raises `RuntimeError` and DQs the whole submission). Heavy per-format canonicalization is deferred to Phase 5; the floor-survival minimum is here.
Output: `src/frame/engine/{postprocess,engine}.py` + CPU contract/frame/guard tests + a GPU-marked smoke test.
</objective>
