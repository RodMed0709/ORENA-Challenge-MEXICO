# Decision: the submission working directory is stale, and it would have shipped rung 06

- **Status:** MEASURED · 2026-08-24 · found while validating rung 54's scoring harness against a
  known number, on the RunPod volume.

## How it surfaced

Rung 54's harness was validated the way this repo validates anything — by making it reproduce a
result we already hold. Scored on UNAM against a fresh merge of rung 42 `checkpoint-4848` it gave
**0.6716** against the archived **0.6744** (Δ −0.0028, inside the GPU-swap drift
[[archived-results-not-bit-reproducible]] documents). Scored on the pod against
`/workspace/submission/resources/model` it gave **0.5494** — a gap of **0.125**, nineteen times
the drift.

Two variables had moved at once, the artifact and the stack, so they were separated: merging
`checkpoint-4848` **on the pod** gave 0.6716 as well.

⇒ the stack is fine and **the artifact is not rung 42**.

The metadata says the same thing without any inference. The container's `args.json` records:

| | container artifact | rung 42 `checkpoint-4848` |
|---|---|---|
| experiment | **`experiments/06-vit-lora`** | `42-merged-corpus` |
| epochs | 3 | 5 |
| learning rate | 2e-5 | 2e-4 |
| `freeze_aligner` | **true** | false |
| `target_modules` | `["all-linear"]` | `all-linear` + the 9 named connector linears |

`config.json`, `generation_config.json`, the tokenizer and the preprocessors are byte-identical,
and both are 4 shards / 750 tensors / ~17.53 GB — which is exactly why nothing looked wrong.

## 🔻 What this is NOT — the correction that matters

**Submission 03 did not ship the wrong model.** It scored **0.5809** on the platform; submission
01, which *was* rung 06, scored **0.4767**. Rung 06's weights cannot produce 0.5809. What was
uploaded was correct, and the leaderboard standing is not in question.

The directory was **reused after the fact**. It is a working directory, not an archive, and
nothing in it announces which model it currently holds.

## 🔴 The trap it sets

`submissions/03-rung42-connector-ood/README.md` opens with *"the build recipe minus the 17 GB of
weights — `resources/model/` is regenerated by the merge command below"*. The design is right: the
weights are meant to be **regenerated**, never trusted in place. But the stale directory on the pod
looks complete, carries the right shard count and the right tokenizer, and would build without a
single warning.

⇒ **Building the next container from `resources/model/` without re-merging ships rung 06**, and
costs a submission slot on a model from six weeks ago. The pool is finite and pre-eval closes
2026-09-01.

## The rule this makes binding

**Never build a container from a `resources/model/` you did not merge in that same session, and
never ship a merged model that has not been scored first.**

One number is enough: score the merged artifact on rung 42's held-out 8 videos before it goes into
an image. A model that is not what you think it is fails that check immediately — this one was
0.125 off — and the check costs one eval, against a submission slot and roughly a day of turnaround.

The directory has been renamed on the volume to
`submission.STALE-holds-rung06-weights-NOT-rung42` with a `READ_ME_FIRST.txt` stating the two
proofs and the correction above, so the next person to open it cannot repeat this.

⚠️ Generalise it past this one folder: **an artifact's identity is a measurement, not a file
path.** `args.json` beside a checkpoint is the cheap version of that measurement and should be read
before anything heavy is built on top.
