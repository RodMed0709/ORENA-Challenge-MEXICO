## DECISIONS — settled verdicts (do NOT re-litigate)
- [[viT-swap-nogo]] — swapping Qwen3-VL's ViT = **NO-GO** (license + full realignment).
- [[qwen-size-ladder]] — next size up = **30B-A3B MoE FP8** (measured wildcard, not the cheap step). 🔒 Gated by [[vit-lora-partial]].
- [[unused-metadata]] — 🔴 **90% of questions carry `secondary_capabilities` we never read**: aggregation supervision is **+77% larger** than we thought (9,762 train questions, not 5,524) at zero annotation cost. Also `generation` (automatic/anchor/manual) unused, and **`clinical_relevance` is all-False** — a second landmine beside `ood`.
- [[aggregation-is-the-gap]] — 🔴 **THE target.** First external reference: a **4B model beats us by 12.5 pts on `aggregation`** (50% of the exam) while we lead `object_recognition` by +14.9. Counting is **not a ceiling** — a smaller model already does it better. **Closing that one gap alone ≈ 59%.**
- [[the-gap-is-the-number-format]] — 🔴 **WHERE the gap is.** `aggregation × ID` is **80.4% `number` format**, and `fo_class` is **not in `aggregation` at all** (it sits entirely in `object_recognition`). Arithmetic: answering 100% of `binary` only reaches 0.4492 — **no path to the target avoids lifting `number` 0.327 → ~0.482**. And `number` is the format that clears its floor by only +8.0 pts (+0.013 on OOD) and returns the mode floor on a black image. **Re-scopes [[class-imbalance-not-counting]].** Zero GPU — the number had been committed for days.
- [[latency-budget-is-pooled]] — 🟢 **the 5 s cap is POOLED, not per-question**: `120 s setup + B × 5 s` per run, read from the official template. With p99 = 0.352 s measured, **self-consistency (k-voting) and higher `max_pixels` are affordable** — both were closed against a ceiling that does not exist as modelled. 🔴 **The risk inverts to COLD START**: imports + weight load + CUDA-graph capture all eat the 120 s setup allowance.
- [[count-calibration-dead]] — 🔴 **post-hoc count calibration is DEAD**, measured three ways (05c): oracle LUT gain **+0.026** vs the **+0.155** needed, ID↔OOD transfer **−0.016** (negative), and `argmax_injective` **False**. Mechanism: true values **2, 3 and 4 all share the same modal prediction (1)** — a LUT can only send `pred=1` one place, so it trades one error for another. **Not fixable with more data.** Leaves synthetic-counting SFT as the only lever left in the group that owns the gap.
- [[resolution-is-not-the-gap]] — 🔴 **the resolution axis is CLOSED, at the gate, for zero GPU.** The "100 %/0 % partition" was an artefact of a non-random n=50: over the full 15,213-frame cache `lapchole` (ID) carries **six** resolutions and its minimum (**230k px**) is below `heico`'s uniform 518k — so **"OOD gets 56 % of ID's visual tokens" is wrong** (~66 % by mean, inverted in the tails). Structurally unanswerable anyway: **130/130 videos have exactly one resolution**, so resolution is **perfectly confounded with video identity**. And accuracy across resolution cells is **non-monotonic**, with two cells resting on one video each. Kills 6b, 11b and 11c unrun.
- [[open-class-vocabulary]] — 🔴 **the class set is OPEN** (`overview.md:17`: "such as … and similar objects"); the organizers' predefined list is **10 classes, not 8**, and **`mesh` + `foreign object` have ZERO examples anywhere**. `silicone loop` is train-only. **Never reshape training classes against val frequencies.** Also: 70% of questions carry no class list although the spec says they do — a possible train/test regime mismatch. 🔴 **And the prompt's 10-item list and the scorer's 10-item list disagree on their 10th element** (`foreign object` vs `Absorbable Hemostatic Agent`): an unrecognised `fo_class` token **RAISES** in `verify()` rather than scoring 0 → RULES §8b.
- [[class-imbalance-not-counting]] — ⚠️ **RE-SCOPED: measures `object_recognition` (where we LEAD), not the gap** — see [[the-gap-is-the-number-format]]. Within that bucket: the failure is **per-CLASS, not per-count**: `gallstone` recall **0.000** (14 train ex.), `needle` 0.511, and a **phantom class** (`silicone loop`, 435 train ex., 0 in val) that is a guaranteed FP. **The ViT LoRA DID work** — `needle` +17.8 pts — `bucket_mean` hid it. But **68% of misses are on classes with >400 examples**, so rebalancing has a low ceiling.
- [[checkpoint-selection-vs-number]] — training erodes `number` on OOD **in both arms, so it is not the ViT** — killed a 7.5 h `vit_lr` run before it was spent. ⚠️ **Its selection claim is RETRACTED**: measured on OOD only; on the full 6252 epoch 2 wins and **RULES §6 is CONFIRMED**.
- [[vit-lora-partial]] — LoRA on the ViT = **PARTIAL**. Settles the *reading*: it neither licenses nor kills the capacity branch. **The ceiling question stays OPEN** until a lower `vit_lr` runs.
- [[next-move-rodrigo-coa-format]] — Rodrigo owns **CoA-format SFT (R1)**; RL is **deferred**.
- [[eval-canonical]] — ONE scoring module (`frame.metrics`): leaf→group via `Capability.group`, ID/OOD from qID; headline = `bucket_mean`, pre_eval reference-only.
- [[no-external-api-for-challenge-data]] — 🔒 **BINDING (DUA):** NO challenge frames/annotations to any external API (Gemini/GPT/Claude/DeepSeek, incl. MCP). Data-touching models must have downloadable weights and run **on-pod**; only Qwen is released, the generator is documented not shipped. Qualifies RULES (new §COMPLIANCE).
- [[coa-generator-qwen32b-onpod]] — R1's scaffold generator = **Qwen3-VL-32B, vision, zero-shot, on-pod** (Apache-2.0, same family as the 8B student). Supersedes the text-only "no pixels" line. Gate: eyeball-50-vision first, **matched 2k-bare control**, emit-only-`<answer>` eval + p99, number-aware selection. (CoA's own teacher was an external API → DUA-forbidden for us, so on-pod is now *required*, not merely chosen.)
- [[coa-sft-published-null]] — 🔴 **the "+16.3 is the format, R1 is the untested cell" premise is FALSIFIED.** The source (arXiv:2603.20116, **our exact backbone**) *does* contain the no-RL scaffold row: **62.0 vs bare-gold SFT's 65.7** (EndoVis2018) — a published wash that loses; the gain is **RLVR's**. Same paper: SFT crushes class-balanced F1cls 20.7→15.3 = **our `clip` attractor, published** (we report no class-balanced metric). Rung 09 **re-scoped, not cancelled**; the one empty cell left is **emit-vs-suppress the trace on one checkpoint**. Retires "+16.3" everywhere.
- [[epoch-matched-control]] — 🔴 **rung 06 never evaluated its own ep3**, so rungs 14 and 15 compared their ep3 against its **ep2**. Rung 14 = faithful NULL (best `margin_OOD` +0.0078, CI includes 0); rung 15 ep3 = +0.0032 headline but ID-driven, `margin_OOD` −0.0110, `number` margin OOD **below floor**, and **0/10** paired cells exclude zero. **Rung 06 stays the best checkpoint.** The missing control is merge+eval, ~1 h, zero training — run it before ANY new training, especially before fusing 14+15. ⚠️ **No run has ever been repeated with a different seed** → no variance estimate at all. Adds RULES §6b.
- [[container-answer-path-audit]] — 🔴 **the shipped container did no normalisation, and a trailing period is AUTO-INCORRECT.** `Number.verify` = `strip().isdigit()`, `Binary.verify` = `in (yes,no)` — so `"1."` and `"Yes."` score wrong, and 16a measured **87%** of off-template `number` answers in that shape (base: 0.0000). Fixed with a format-agnostic `normalize_answer` (the container cannot know the format — `Request` has no `answer_format`), verified against the SDK's real verifiers: 7 repairs, **22 inputs byte-identical**. 🟢 The adversarial-abort risk was measured to **0 hits across 146,004 committed answers** and deliberately NOT filtered — the SDK says the detector exists to stop output tuning. ⚠️ `answer_postprocess` exists in the engine and NOT in the container: a fix through the hook does not reach the shipped artifact.
- [[prompt-only-pointing-collapses]] — 🔴 **`len(points)` is dead as an inference-time trick.** Both pointing arms lose to the bare integer in EVERY cell (a1 OOD margin −0.116, a2 −0.139 vs control −0.003), at 3.4× the latency. Mechanism is visible and degenerate: **a2 emits exactly ONE point on all 681 questions** (`mean_pred` 1.0000) — the model does not enumerate, so the derivation reads a constant and AMPLIFIES the undercount (bias −2.52 vs −0.66). ⚠️ Bounds the **prompt-only** path, which Alghisi themselves predicted; their +80.9 came WITH point-supervised LoRA. Stays open as a training target, gated on 16b.
- [[zero-is-format-localized]] — 🔴 **the missing zero is a FORMAT deficit, not a missing capability.** The fine-tuned model says `no` fluently (binary emit_absent 0.82) and **never says `0`** (number 0.008/0.017) — exactly matching supervision that has 1,008 `no` golds and **zero** numeric zeros. The base is NOT a counter-example: it is a zero **attractor** that negates **83% of PRESENT** cases, so HoloCount's 96.4% does not transfer and there is nothing to restore. ⇒ minting is licensed for `number` ONLY, halving the plan. 🔴 **Bigger finding:** fine-tuning created a **format fragility the base lacks** — on off-template phrasings `ft` emits `"1."` on **87%** of number questions, which `Number.verify` **auto-fails** (base: 0.0000). Fixable with one line in the existing `answer_postprocess` hook.
- [[submission-01-rung06]] — 🟢 **first submission shipped** (`Qwen3VL-8B-FT-ViT-LLM-v1`). Exposed a 🔴 **conflict between the platform interface (`/input/batch-frames.zip`) and the organizers' own template (`/input/frames/<qID>.png`)** — the container now accepts both and logs the `/input` inventory, or a silent all-empty `answer.json` would have burned a submission. Also the **ground truth of what rung 06 actually is**, read from `adapter_config.json`: pure LoRA with all base weights frozen, and **two** excluded modules (`visual.merger` + `visual.deepstack_merger_list`), not one.
